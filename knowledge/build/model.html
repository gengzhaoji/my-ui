ESM 与 CommonJS 模块系统对比 #

以下是 ECMAScript Modules (ESM) 和 CommonJS (CJS) 两种 JavaScript 模块系统的对比：

1. 语法差异 #

特性CommonJS (CJS)ESM (ES Modules)
导出module.exports = ... 或 exports.foo = ...export default ... 或 export const foo = ...
导入const module = require('path')import module from 'path'
动态导入require() 可在任何位置使用import() 返回 Promise（动态导入）

CommonJS 示例：

// 导入模块
const fs = require('fs');
const { myFunction } = require('./utils');

// 导出模块
module.exports = {
  data: 123,
  getData: () => console.log('Data fetched')
};

// 另一种导出方式
exports.myVar = 'Hello';

ESM 示例：

// 导入模块
import fs from 'fs';
import { myFunction } from './utils.js';
import * as utils from './utils.js';

// 命名导出
export const data = 123;
export function getData() {
  console.log('Data fetched');
};

// 默认导出
export default {
  apiKey: 'abc123',
  fetchData: () => {/* ... */}
};

// 动态导入
const loadModule = async () => {
  const module = await import('./dynamic-module.js');
  module.run();
};

2. 加载机制 #

特性CommonJSESM
加载方式同步加载（运行时）异步加载（编译时静态解析）
运行时支持动态路径（如 require(path)）路径必须是静态字符串（除 import()）
顶层 this指向当前模块指向 undefined（严格模式）
解析时机执行时解析依赖预解析依赖关系
循环依赖处理支持（可能部分导出未初始化）支持（绑定为引用，值实时更新）

3. 环境支持 #

环境CommonJSESM
Node.js原生支持（传统默认）需 .mjs 扩展名或 package.json 设置 "type": "module"（Node 12+）
浏览器不支持（需打包工具转换）原生支持（<script type="module">）
工具链Webpack/Rollup 等可处理现代构建工具原生优化（支持 Tree Shaking）
Deno不支持原生支持
Bun支持优先支持

4. 关键特性对比 #

特性CommonJSESM
Tree Shaking不支持（导出对象动态引用）支持静态分析，优化未使用代码
顶层作用域非严格模式（除非手动启用）始终严格模式（use strict）
互操作性可通过 import 引入 ESM（Node 中）可通过 import 引入 CJS（但无命名导出）
性能同步加载可能阻塞异步加载更高效
未来兼容性逐渐被取代JavaScript 官方标准

5. 使用场景 #

CommonJS 适用场景 #

  • Node.js 传统项目：遗留系统或未迁移的代码库
  • 需要动态导入路径：根据运行时条件加载模块
  • 同步依赖解析：需要立即使用导入的模块内容
  • 脚本文件：简单的 Node.js 脚本和工具

ESM 适用场景 #

  • 现代前端框架：React、Vue、Angular 等项目
  • 浏览器原生模块：无需打包直接在现代浏览器运行
  • 需要 Tree Shaking：优化生产环境包大小
  • 跨环境代码：同时在浏览器和 Node.js 中运行
  • 新项目开发：所有现代 JavaScript 项目的推荐标准

6. 互操作性示例 #

在 ESM 中使用 CommonJS 模块 #

// 导入整个 CommonJS 模块
import cjsModule from './commonjs-module.cjs';

// 导入特定属性（需模块支持）
import { namedExport } from './commonjs-module.cjs';

console.log(cjsModule.defaultExport);
console.log(namedExport);

在 CommonJS 中使用 ESM 模块 #

// 动态导入（异步方式）
const loadESM = async () => {
  const esmModule = await import('./esm-module.mjs');
  console.log(esmModule.default);
  console.log(esmModule.namedExport);
};

// 同步方式（不推荐）
import('./esm-module.mjs')
  .then(module => {
    console.log(module.default);
  });

在 package.json 中配置 #

{
  "name": "my-project",
  "type": "module", // 默认使用 ESM
  "main": "index.js",
  "exports": {
    ".": {
      "import": "./esm/index.js",   // ESM 入口
      "require": "./cjs/index.cjs" // CommonJS 入口
    }
  }
}

7. 迁移策略 #

  1. 渐进式迁移：

    • 将现有文件保留为 .js 或重命名为 .cjs
    • 新文件使用 .mjs 扩展名
    • 在 package.json 中添加 "type": "module"

  2. 双模式入口：

    {
  "exports": {
    "import": "./dist/esm/index.js",
    "require": "./dist/cjs/index.js"
  }
}

  3. 转换工具：

    • 使用 esbuild、babel 或 tsc 进行模块转换
    • 利用 unbuild 或 microbundle 生成双模式包

8. 总结对比表 #

维度CommonJSESM
标准类型社区标准语言官方标准
加载机制同步加载异步加载
解析方式运行时动态解析编译时静态解析
严格模式默认不启用始终启用
浏览器支持需要打包转换原生支持
Tree Shaking不支持原生支持
循环依赖支持但有限制完善支持
未来前景维护模式发展方向
